## What this system is

Network Access Control (NAC) is the **gate at the edge of the network**: before a device is allowed onto the LAN, Wi-Fi, or VPN, NAC checks *what it is* (identity) and *how healthy it is* (posture), then grants access, restricts it, or quarantines it. It's the network-layer enforcement arm of [endpoint security](../endpoint-security-architecture) and [zero trust](../zero-trust-architecture): the old "it's plugged into our switch, so it's trusted" assumption is replaced with "prove identity and posture first." Think of NAC as **802.1X on the wire, plus a health check, plus a quarantine loop.**

```mermaid
flowchart LR
  D[Device] -->|connect request| S[Switch / AP / VPN gateway]
  S --> Q{Is the device known?}
  Q -->|no - 802.1X fails| QZ[Guest / quarantine VLAN]
  Q -->|yes - identity proven| P{Posture OK?}
  P -->|no - out of date / missing AV| QZ
  P -->|yes| A[Full / employee VLAN]
  QZ -->|remediation - patch, update| P
```

## The three layers of NAC

| Layer | What it does | The failure if it's missing |
| --- | --- | --- |
| **802.1X authentication** | Port-based auth via RADIUS before the port/AP gives access | Any physical jack is a trusted port; unmanaged devices get straight in |
| **Posture assessment** | Checks AV present/current, patches, policy compliance after auth | A valid identity (even stolen) with a compromised device passes |
| **Enforcement / quarantine** | Drops non-compliant devices onto a remediation VLAN until fixed | Non-compliant devices sit on the trusted LAN indefinitely |

The mental model: **identity gets you onto the wire; posture gets you into the trusted zone.** NAC is the mechanism that makes "prove it before you're inside" literal at layer 2 — a sick or unknown device is contained to a guest/remediation network, not just "flagged" on a dashboard.

## The request path: device connects to the network

```mermaid
sequenceDiagram
  participant D as Device
  participant AP as Switch / AP / VPN GW
  participant R as RADIUS server
  participant P as Policy / posture server
  participant Q as Quarantine VLAN

  D->>AP: connect - EAP (802.1X) request
  AP->>R: forward auth request
  R->>R: validate device + user identity
  alt identity denied / unknown
    R-->>Q: access denied - quarantine or guest VLAN
  else identity accepted
    R-->>P: check posture (AV, patches, policy)
    P-->>AP: access-accept - trusted VLAN
    Note over D,Q: compliance lost later
    P-->>Q: downgrade to quarantine on posture change
  end
```

The key modern shift: **identity is the primary key, posture is the secondary check.** NAC used to be "can this MAC address in?" — now it's "is this a real, enrolled, attested device with a current posture?" That's why NAC is tightly coupled to [MDM](../mobile-device-management-mdm) and endpoint enrollment: the posture data has to come from a trusted source on the device, not from what the device *claims* about itself.

## NAC vs the things it gets confused with

| Thing | What it actually is | Versus NAC |
| --- | --- | --- |
| **802.1X** | The protocol/port-auth mechanism (EAP + RADIUS) | NAC's authentication layer, not the whole thing |
| **Firewall / microsegmentation** | Layer 3–7 filtering *between* zones | NAC gates the *entry* edge; firewalls gate traffic *after* entry |
| **MAC filtering** | Allow-list of MAC addresses | Trivial to spoof; NAC adds real identity + posture on top |
| **SASE / ZTNA** | Cloud edge access control for remote/cloud | The same idea, moved off-LAN; NAC is the on-prem LAN version |

The strategic read: **NAC secures the physical LAN edge; [SASE](../sase) / ZTNA secures the remote-and-cloud edge.** Modern estates don't choose one — they get NAC for the office floor and SASE for the rest of the world, with the same identity/posture logic underneath.

## Why NAC projects disappoint (and what actually works)

| Disappointment | The real cause | The fix |
| --- | --- | --- |
| **"We bought NAC and nothing happened"** | Enforcement never turned on; it was deployed observe-only | Decide the quarantine policy *before* rollout; enforce on a pilot VLAN first |
| **Posture checks trusted the device's claim** | Agent/device report not validated against a trusted source | Require an enrolled [endpoint](../endpoint-security-architecture) / MDM attestation, not a self-report |
| **Real devices got quarantined** | Stale posture source (old AV definition list, expired certs) | Revalidate posture data, not assumptions; allow remediation to be fast and self-service |
| **Guests / printers / IoT broke** | Network assumed all devices are managed | Non-managed categories get explicit guest/IoT policies, not a silent default-deny |
| **Quarantine loop was a dead end** | Devices stuck in quarantine with no path back | A remediation portal the user actually sees, with one-click patch/update flows |

The pattern that works: **NAC as a hygiene gate with a fast remediation loop, not as an access-control barricade.** Enforce on a small-but-real VLAN, measure how often genuine users hit quarantine, and make "fix it and come back" a 5-minute path rather than a ticket.

## The failure modes an architect owns

- **Enforcement never enabled** — the classic: NAC deployed in monitor-only mode forever, so it reports but never blocks.
- **Trusting the device's own claim** — no enrolled endpoint identity, so a compromised-but-"healthy"-claiming device walks straight through.
- **Stale posture sources** — checking against an AV definition list nobody updates; posture checks confirm yesterday's truth.
- **One-size quarantine** — printers, HVAC, and unmanaged guests all dumped into a "quarantine" with no path back or wrong per-category policy.
- **No BYOD story** — personal devices with no agent get default-deny or default-trust, instead of a designed guest/remediation posture.
- **NAC for the LAN only** — remote/cloud devices are invisible to the gate, so the office is protected and everything else isn't (hence [SASE](../sase)).

## Tester checklist

- **Identity gate**: connect a device with no/unknown identity and confirm it lands on guest/quarantine, not the trusted VLAN.
- **Posture gate**: connect a known identity with a deliberately stale AV/OS and confirm access is downgraded to quarantine with a visible remediation path.
- **Enforcement reality**: confirm quarantine is *enforced* (traffic actually blocked), not merely logged — run a probe from a quarantined port.
- **Remediation loop**: take a quarantined device, apply the fix, and confirm it re-authenticates into the trusted VLAN within the target time, self-service.
- **Posture-source truth**: break the posture source (expire the AV definition list, kill the MDM attestation) and confirm devices are *not* auto-granted on stale data.
- **Guest/IoT segregation**: connect a printer/guest and confirm they get the designed IoT/guest policy, never the trusted employee VLAN.
