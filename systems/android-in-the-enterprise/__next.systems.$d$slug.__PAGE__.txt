## What this system is

Android corporate management is built around one idea: **separation of worlds**. Android's enterprise APIs split a single device into a *personal* side and a *managed* *work profile* side (or a fully-managed single profile for company-owned). Corporate apps, data, config, and wipe live entirely inside the work container — the personal side stays the user's.

```mermaid
flowchart LR
  Device[Device<br/>factory reset] -->|scan once| Enroll[QR scan / NFC<br/>enrollment token]
  Enroll -->|enroll DPC| EMM[EMM server<br/>DPC installed]
  EMM -->|managed Google Play| Work[Work profile<br/>corporate apps]
  Work -->|hard isolation| Personal[Personal space<br/>user data]
  EMM -->|compliant| Managed[Managed and isolated]
```

```mermaid
flowchart LR
  E[EMM: Intune / Workspace One / MobileIron] -->|managed Google Play + policy| D[Device]
  D --> W[Work profile<br/>corporate apps + data]
  D --> P[Personal space<br/>user's apps + photos]
  W -->|isolation| P
```

## The three management models

| Model | BYOD (work profile) | COPE (fully managed) | Dedicated (kiosk) |
| --- | --- | --- | --- |
| Ownership | User's device | Company-owned | Company-owned |
| Corporate apps | In work profile | Whole device is corporate | Single/multi-app kiosk mode |
| User privacy | Personal side untouched | Personal apps possible but weaker promise | No personal use |
| Wipe | Wipes only work profile | Full factory reset | Full reset |
| Best fit | Employee phones | Sales/field fleets | POS, signage, rugged devices |

## Provisioning a device (no user input needed)

```mermaid
sequenceDiagram
  participant Dev as Device (factory reset)
  participant QR as QR / provision network
  participant EMM as EMM server
  participant G as Managed Google Play

  Dev->>QR: scan QR (or boot to hotspot / NFC tap)
  QR-->>Dev: EMM endpoint + enrollment token
  Dev->>EMM: enroll DPC
  EMM->>G: claim device in managed Play
  EMM->>Dev: push work profile + managed config
  Dev->>Dev: corporate apps install into work profile only
```

Provisioning bypasses typing: factory-reset a device, scan a QR code (or tap an NFC tag in Android 10+), and the EMM takes over within minutes. This is how fleets get onboarded in warehouses and clinics without IT hands.

## How the work profile really isolates

- Android runs the personal and work sides as **separate users** under one OS; the work container is encrypted and permission-scoped.
- **Managed config** (per-app JSON-like settings) pushes policies directly into apps via Google Play — no MDM agent inside each app required.
- IT can `wipe the work profile only` on BYOD, leaving photos and personal apps intact — the legal/UX reason employees accept corporate EMM.
- Work apps' **network** can be forced through always-on VPN and DPC-managed certificates; data does not cross profiles without managed-mode paths.

## Tester checklist

- Enroll twice (BYOD work profile + a COPE device) and verify which management capabilities each exposes in the EMM console.
- Confirm work-profile wipe removes corporate apps/data but preserves personal data, and that the device rejoins cleanly.
- Push a managed config to an app and verify it arrives without user action, and that only work-side instances read it.
- Check kiosk/dedicated mode locks correctly: no home button escape, no personal apps, auto-restart on crash.
