Microsoft Graph API

One API for all of Microsoft 365: users, mail, drives, Teams, Intune — the unified Graph model, delegated vs app-only auth, and the paging and throttling rules you live by.

DeveloperBackendEnterprise ArchitectSecurity Architect#api#cloud#identity#architecture

What this system is

Microsoft Graph is the single API for Microsoft 365: instead of a separate API for Exchange, OneDrive, Teams, SharePoint, Entra ID, and Intune, everything hangs off one service rooted at https://graph.microsoft.com. Company data — users, mail, files, chats, devices, groups — is a graph of entities with relationships you traverse with REST verbs (or GraphQL-style select lists).

The model: entities and relationships

Rendering diagram…

The Graph is a true graph: navigate relationships in either direction (GET /me, GET /me/directReports, GET /groups/{id}/members). Key entry points:

ResourceHow you reach it
Me / usersGET /me, GET /users/{id}, GET /users?$filter=...
GroupsGET /groups, GET /groups/{id}/members
MailGET /me/messages?$top=10, POST /me/sendMail
CalendarGET /me/events, booking resources
Drives/filesGET /me/drive/root/children, SharePoint sites & lists
Teams/chatsGET /me/chats, POST /chats/{id}/messages
Devices (Intune)GET /deviceManagement/managedDevices

The $select, $filter, $expand, $top, $orderby, and $skip OData query options are the whole game: they control what comes back, so you fetch exactly what you need instead of dumping a whole entity.

Delegated vs application (app-only) auth

Rendering diagram…
  • Delegated: the app acts as a signed-in user, with scopes (like Mail.Read) that the user (or tenant admin) consents to. The token represents user + app.
  • Application-only: no user — the app has tenant-level roles (e.g. admin-granted Mail.Read for the whole org). This is the dangerous one: an app-only token reaches everything its app-level permissions allow, no individual user in the loop.

The recurring incident: an app registered with Application permissions when it only needed Delegated — one bad consent and a background job can read every mailbox. Least privilege means choosing the narrowest model that does the job.

The API mechanics: tokens, throttling, pagination

Rendering diagram…
  • Auth: always a Bearer token from MSAL/OAuth 2.0 — never the user's password. Tokens are short-lived; refresh before expiry.
  • Pagination: Graph returns @odata.nextLink — follow it for the next page. Don't re-run the same query; don't assume a single response is the whole set.
  • Throttling: Graph has rate limits (hit 429 with a Retry-After). The contract: fetch less, cache more, and honor backoff — a hammering batch app gets slowed by design, and retrying too fast makes it worse.
  • Batch: $batch lets you combine up to 20 requests into one — the answered prayer for chatty apps that would otherwise pad a round-trip per call.

The mistakes repeatedly remembered

  • Using app-only permissions for a workflow that acts on a single user's behalf — every mailbox becomes readable.
  • Ignoring pagination and paginating by hand — a 10k-row migration that assumed one response is a classic.
  • No throttling handling: re-firing instantly on 429 triggers the very backoff the API is enforcing.
  • Storing a user's password to "log in and sync mail" instead of using delegated auth properly.
  • Treating GET /me as "any user": with app-only auth, /me doesn't exist as a personal context — you must target /users/{id}.

Tester checklist

  • Confirm delegated vs app-only: a background job must not have scopes it can't use, and an app-only token must not be able to read GET /me.
  • Hit a paginated endpoint and verify you follow @odata.nextLink end-to-end (all pages collected, none skipped).
  • Hammer a throttled endpoint and verify your client honors Retry-After instead of spinning.
  • Test least privilege: a Mail.Read-only app cannot write or read other data types; add the minimal scope and confirm a forbidden call returns the expected error.
  • Batch-test: combine 20 small calls into one $batch and confirm it saves round-trips without breaking errors.
