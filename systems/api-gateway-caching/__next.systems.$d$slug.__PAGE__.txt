## What this system is

A cache at the **edge** (CDN or gateway) is the biggest latency win available: a hit never touches your origin. This guide focuses on how cache entries are decided and invalidated — the interactive diagram below is the same flow you can drag around.

```mermaid
sequenceDiagram
  participant C as Client
  participant G as API Gateway
  participant E as Edge Cache
  participant O as Origin Server

  C->>G: GET /api/users
  G->>E: lookup cache key
  alt cache hit
    E-->>G: serve cached response
  else cache miss
    E->>O: miss, forward to origin
    O-->>G: 200 + Cache-Control
  end
  G-->>C: serve response to client
```

## The cache decision, in plain words

1. The gateway computes a **cache key** — typically `method + path + normalized query + auth scope`.
2. It looks the key up in the edge cache.
3. **Hit**: serve directly. **Miss**: forward to origin.
4. The origin answers with a `Cache-Control` header that says *how long it may be cached (and by whom)*.
5. On the first request after expiry, the gateway can serve the stale copy while fetching fresh data in the background = **stale-while-revalidate**.

## Headers that matter

| Header | Meaning |
| --- | --- |
| `Cache-Control: max-age=60` | Cache for 60 s |
| `Cache-Control: public` | Shared caches may store it |
| `Cache-Control: private` | Only the browser may store it — often right for user-specific data |
| `ETag` | Validator: revalidate with `If-None-Match` for a cheap `304` |
| `Vary: Accept-Encoding` | Cache key must include the language/encoding of the response |

## The classic bugs

- **A `private`-only response cached publicly** → user A sees user B's dashboard.
- **Ignoring the cache key for auth** → authenticated and anonymous users sharing entries.
- **Unbounded `max-age` on mutable data** → broken or stale product data until expiry.
- **Missing `Vary`** → a caches compressed and uncompressed variants under the same key.

## Tester checklist

- Inspect the `Cache-Control` header on responses — is `private` data marked private?
- Change a user's profile and confirm the edge does not still serve the old version.
- With `stale-while-revalidate`, confirm the first post-expiry request is still fast (stale served).
- Check `Age` header to see how old a cached response actually is.
