## What this system is

Linux powers nearly everything a corporation runs that isn't on a desktop — API servers, databases, CI runners, network appliances, cloud instances. "Managing Linux" at scale isn't SSHing into hosts; it's making hosts **interchangeable** so a crashed one disappears and a fresh one looks identical.

```mermaid
flowchart LR
  G[Golden image / IaC] --> C[Configuration as code<br/>Ansible/Terraform/Puppet]
  C --> H1[Server 01]
  C --> H2[Server 02]
  C --> H3[Server 03]
  H1 --> P[Patch pipeline]
  H2 --> P
  H3 --> P
  P --> I[(Monitoring / inventory)]
```

## The two mental models

| Old way (pets) | New way (cattle / immutable) |
| --- | --- |
| SSH in, fix it live | Never patch a live server; build a new image |
| Drift over months | Config is code, auditable in git, reproduced everywhere |
| Hand-written playbooks | Idempotent, versioned, tested in CI |
| Servers have names & moods | Servers have roles and are disposable |

Most enterprises run a mix: stateful databases still demand care, stateless tiers are freely rotated. The rule that holds everywhere: **the source of truth is code, not a shell session.**

## The pieces that matter

```mermaid
flowchart TB
  subgraph Build["Build"]

  C --> D
  D --> E
  E --> F
  F --> G
```

## The patch cycle (the drumbeat that never stops)

- Patch **rings** mirror Windows Autopatch: a canary host gets the update first; only on success does it roll to broad. A bad kernel in one ring doesn't take down production.
- **Secrets** never ship in images or repos — pulled at boot from a vault/secret manager ([identity best practice](../authentication-vs-authorization)) with short-lived credentials.
- **Reboots** are planned, drained, and verified — orchestrated, never chaotic.
- Vulnerability triage is a *risk* calculation, not an all-or-nothing: you patch what's reachable first.

## Tester checklist

- Rebuild a host from the golden image and diff it against peers — drift should be ~zero or a documented exception.
- Kill a stateless node mid-traffic and confirm orchestration reconstitutes it without user-visible impact.
- Roll a deliberately bad package to the canary ring and verify the ring's monitors catch it *before* broad rollout.
- Verify a fresh host cannot boot with secrets available in its filesystem (secrets come from the vault only).
