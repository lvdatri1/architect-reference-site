## What this system is

Apple devices in a corporation are managed remotely through **MDM** (mobile device management) once they're enrolled via **Apple Business Manager (ABM)**. Enrollment happens at first boot — before the user ever signs in — so the device is corporate-owned, **supervised**, and policy-controlled from day one. This is the Apple answer to Windows' domain join.

```mermaid
flowchart LR
  Vert[Device purchased / registered] -->|serial added| ABM[Apple Business Manager]
  ABM -->|automated enrollment via DEP| MDM[MDM: Intune / Jamf]
  MDM -->|supervision + config profiles| D[Device]
  D -->|inventory + compliance| MDM
  MDM -->|approve/distribute| App[Apps via App Store / VPP]
  App --> D
```

## How enrollment actually happens

```mermaid
sequenceDiagram
  participant D as Device (out-of-the-box)
  participant ABM as Apple Business Manager
  participant MDM as MDM server
  participant U as User

  D->>ABM: activation at boot, sends serial
  ABM-->>MDM: "this device is managed — handshake"
  MDM->>D: install MDM profile → device is supervised
  MDM->>U: accept portal, sign in with work identity
  MDM->>D: push config profiles (Wi-Fi, VPN, restrictions)
  MDM->>D: approve + push apps, VPP licenses
  Note over MDM,D: no user bypass - supervision locks enrollment, remote wipe always available
```

Key actors:
1. **ABM** — the identity catalog of corporate Apple devices (and volume app licensing). Without ABM, the device belongs to the user, not the company.
2. **MDM server** — Intune/Jamf/Workspace One command the device via Apple's DEP/MDM protocol.
3. **Supervised** — the elevated state Apple gives *corporate-claimed* devices: allows config profiles like "always on VPN", deep restrictions, and App Store-only app installs that cannot be overridden.

## Supervised vs personal devices

| | Personal device (BYOD) | Supervised/ABM corporate |
| --- | --- | --- |
| Belongs to | The user | The company |
| Config depth | Limited (work profile-ish controls) | Full: restrictions, payloads, app lockdown |
| App install | User freedom | Only approved, MDM-approved apps |
| Wipe | User's consent | Full remote wipe at any time |
| Umbrella | light touch | Heavy, always-on controls |

## Why "App Store-only" is the interesting security lever

On a supervised device, the MDM can forbid **everything except the App Store** — killing sideloaded/signed-app attack surface and rogue marketplaces in one boolean. Combined with **managed Apple IDs** (no personal identity dependency), FileVault (macOS full-disk encryption), and hardware-backed [SEP / Secure Enclave](../zero-trust-architecture), the device behaves like a thin corporate client.

## Tester checklist

- Enroll a fresh supervised device via DEP automation and verify the user cannot unpair/enroll-away (supervision holds).
- Confirm a config profile lands (Wi-Fi/VPN) within the check-in window, and that violating restrictions is blocked, not just warned.
- Verify VPP app licensing of a flagged app reaches exactly the assigned devices — license count matches device count.
- Wipe drill: confirm remote wipe/`Find My`-style outstanding claim works against a lost device within policy SLAs.
