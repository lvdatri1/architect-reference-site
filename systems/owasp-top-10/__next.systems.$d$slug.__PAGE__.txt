## What this system is

The **OWASP Top 10** (2021) is the de-facto checklist of the most common and dangerous web-app weaknesses. It is about *implementation risk* — the flaws that live in code — and complements design-level methods like STRIDE and Zero Trust.

```mermaid
flowchart LR
  subgraph Ranked["Top 10 (by exploitability + prevalence)"]
    A01[1 · Broken Access Control]
    A02[2 · Cryptographic Failures]
    A03[3 · Injection]
    A04[4 · Insecure Design]
    A05[5 · Security Misconfiguration]
    A06[6 · Vulnerable & Outdated Components]
    A07[7 · Identification & Auth Failures]
    A08[8 · Software & Data-Integrity Failures]
    A09[9 · Security Logging & Monitoring Failures]
    A10[10 · SSRF]
  end
  Ranked -->|feed into| DEF[Defensive checklist: req-by-req & build-time gates]
```

## The ten, distilled

| # | Category | One-line meaning | Classic fix |
| --- | --- | --- | --- |
| A01 | Broken Access Control | Users reach things they shouldn't | Enforce authz server-side, deny-by-default, no client-side `role` fields |
| A02 | Cryptographic Failures | Crypto used wrong or not at all | TLS everywhere, strong KDFs, no homemade crypto, encrypted secrets at rest |
| A03 | Injection | Untrusted data executed as code | Parameterized queries, strict validation, output encoding |
| A04 | Insecure Design | The *design* has no guardrails | Threat model first, deny-by-default, rate limits, architecture review |
| A05 | Misconfiguration | Defaults, debug modes, open buckets | Config pipelines, security defaults, disable verbose errors |
| A06 | Vulnerable Components | Old libs with known CVEs | Dependency scanning, keep inventory, patch in SLA |
| A07 | ID & Auth Failures | Weak login, session bugs | MFA, strong password rules, lockout, secure session handling |
| A08 | Integrity Failures | Deserialization, tampered pipelines | Signed artifacts, safe deserialization, check integrity |
| A09 | Logging & Monitoring Gaps | Attacks invisible until too late | Structured + complete logs, alerting on anomalies, audit trails |
| A10 | SSRF | Server fetches attacker-chosen URLs | Validate allow-listed destinations, no redirects to internal, metering |

## How the "top" is decided

The list is **data-driven**: it re-ranks by frequency in real scanners, reported incidents, and CTFs — not by academic severity. That's why *Design* and *SSRF* entered in 2021: they were causing outsized damage even at low frequency.

```mermaid
sequenceDiagram
  participant S as Source (scanners, bug bounties, CVEs)
  participant O as OWASP
  participant DEV as Development teams
  participant A as Auditors / pentesters

  S->>O: occurrences + exploit data
  O->>O: aggregate & re-rank ~ every 3–4 years
  O->>DEV: Top 10 + ASVS reference
  DEV->>A: verify checklist gates in CI + reviews
  A-->>DEV: findings mapped back to categories
```

## Use it as a *gate*, not a scoreboard

- **Per feature**: at design/implementation, test against the relevant rows (an auth endpoint → A01/A07/A02; an import/export → A08/A03).
- **In CI**: run the automated scans behind it (ZAP, Semgrep) wired to fail the pipeline on Hard/High findings.
- **Interviews & reviews**: if you can't explain *how* you control A01, you have a gap — the Top 10 makes that conversational and specific.
- **It is not a threat model** — it won't tell you a *specific* system's risk profile; pair it with STRIDE for design and Zero Trust for enforcement.

## Tester checklist

- Map your app's endpoints against all ten and note which tax *at least one* control per applicable row.
- Confirm access control is server-enforced: stripping client-side flags must break elevated features.
- Enable verbose errors in staging and confirm the *staging* baseline is not your production config.
- Spot-check the dependency scanner: known-CVE packages must block the build, not just warn.
