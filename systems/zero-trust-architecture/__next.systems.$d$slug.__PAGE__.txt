## What this system is

Classic network security is a **castle**: walls (firewall) around an internal "trusted" LAN, where anything inside is assumed safe. **Zero Trust** inverts that assumption — every request, from anywhere, is untrusted until it proves identity, context, and policy.

```mermaid
flowchart TB
  subgraph Castle["Traditional perimeter model"]
    direction LR
    U1[User] --> FW1[Firewall / VPN] --> INSIDE1[(Trusted LAN)]
    INSIDE1 --> S1[(Server)]
    INSIDE1 --> S2[(Database)]
    INSIDE1 --> S3[(Old internal tool)]
  end

  subgraph ZT["Zero Trust model"]
    direction LR
    U2[User] -->|"verify identity + policy"| POL2[Policy engine<br/>continuous authz]
    POL2 -->|"microsegmentation"| S4["App A"]
    POL2 -->|"append network path"| S5["App B"]
    POL2 -->|"never implied trust"| S6["App C (least privilege)"]
  end
```

## The three pillars

1. **Assume breach** — design as if the attacker is already inside the network. Lateral movement is the target to stop.
2. **Identity is the new perimeter** — access is granted per user + device + context, not per subnet. Mutual TLS (mTLS) authenticates both sides.
3. **Enforce every request** — no "trusted once, trusted forever": re-evaluate on each session, each request.

## Key building blocks

| Block | Role |
| --- | --- |
| Identity provider (SSO) | Source of user identity and posture signals |
| Policy engine (PEP/PDP) | Decides every allow/deny per request + context |
| mTLS (service mesh) | Encrypts + authenticates *between services*, not just at the edge |
| Microsegmentation | Logical isolates per workload so a compromise can't hop services |
| Just-in-time access | Privileged access granted for a window, then revoked |

## A request under Zero Trust

```mermaid
sequenceDiagram
  participant U as User
  participant EC as Enforcer (edge / proxy)
  participant PE as Policy engine
  participant IDP as Identity provider
  participant S as Backend service

  U->>EC: request (token + device posture)
  EC->>PE: evaluate identity, device, context, risk
  PE->>IDP: verify login + posture
  IDP-->>PE: trusted (or deny)
  PE-->>EC: decision: allow with minimal scope
  EC->>S: mTLS handshake, audited, scoped
  S-->>U: response (limited to allowed actions)
```

## Why teams adopt it

- **Lateral movement dies**: even with VPN access, a user only reaches what policy allows per workload.
- **Blast radius shrinks**: a stolen workstation does not equal "everything".
- **Remote-anywhere becomes safe**: zero network sprawl, zero "just add my home IP".
- **Costs are real**: identity sprawl, per-service policies, and latency from continuous checks — budget for them.

## Tester checklist

- Verify policy is evaluated on *every* request, not cached at login.
- Confirm mTLS actually fails when a service is impersonated.
- Check that a device with a revoked posture signal loses access promptly (not at next login).
- Look for bootstrap holes: is there a path that trusts "internal network" implicitly?
