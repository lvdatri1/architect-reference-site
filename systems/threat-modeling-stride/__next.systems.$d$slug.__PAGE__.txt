## What this system is

Threat modeling is not a pentest — it happens **before code** (or before major changes) by asking "if someone attacks us, which of these six generic threats would bite?" STRIDE names the six:

| Letter | Threat | The attacker… | Example |
| --- | --- | --- | --- |
| **S** | Spoofing | pretends to be someone else | forging a username / token |
| **T** | Tampering | modifies data or code | changing a transfer amount mid-flight |
| **R** | Repudiation | denies doing something | "I never placed that order" (no audit trail) |
| **I** | Information disclosure | reads data not meant for them | viewing another user's dashboard |
| **D** | Denial of service | makes the system unusable | flooding an endpoint |
| **E** | Elevation of privilege | gains rights they lack | turning a reader into an admin |

```mermaid
flowchart LR
  DF[Draw data-flow diagram] --> EN[Enumerate STRIDE threats<br/>per trust boundary]
  EN --> RK[Rank by likelihood x impact]
  RK --> MI[Mitigate<br/>+ validate with a spike]
  MI --> DO[Document decisions & owners]
  DO -.->|iterate once a quarter| EN
```

## How to run a five-minute pass

1. **Draw it**: components, data stores, trust boundaries (the dashed lines where identity flips — UI vs API vs DB).
2. **For each boundary, ask STRIDE**: at the crossing from the internet → app, S and I and D dominate; at app → DB, T and I dominate.
3. **Score 1–3 each**: likelihood × impact. Fix anything ≥ 6 first — don't gold-plate the rest.
4. **Prove mitigations**: tests that would fail if a threat returned (see checklist).

```mermaid
flowchart TB
  TRUST1[User / Browser<br/>untrusted] -->|over the internet| TRUST2[API layer<br/>partially trusted]
  TRUST2 -->|1 mTLS + ACLs| TRUST3[Database<br/>trusted]
  TRUST1 --> B1{Spoofed token?}
  TRUST2 --> B2{Tampered payload?}
  TRUST2 --> B3{Data leak via over-fetching?}
  B1 --> M1[verify signature + exp]
  B2 --> M2[sign request / validate model]
  B3 --> M3[column-level access control]
```

## Common pitfalls

- **Modeling threats you can't ship** — a mitigation that never ships is worse than none ("documented as risk" ≠ fixed).
- **Forgetting the insider** — the most expensive threats often sit *inside* trust boundaries (shared DB access).
- **OWASP ≠ STRIDE** — OWASP Top 10 is implementation bugs; STRIDE is design. Both belong on the roadmap, at different stages.

## Tester checklist

- Choose the top-ranked threat and write a test that *would have* caught it.
- Verify mitigations exist at the right trust boundary, not one hop downstream.
- Confirm repudiation is covered: audit logs include actor, action, timestamp, and are append-only.
- Re-run the DFD when the design changes — models rot fast.
