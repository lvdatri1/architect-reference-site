## What this system is

**PIM** (Azure PIM is the canonical product; the pattern exists everywhere) replaces *"you're an admin all day"* with *"you can ask to be an admin for 30 minutes."* Standing privileged access is the single most valuable compromise target in an estate. PIM makes privilege **temporary, approved, recorded, and auto-expiring**.

```mermaid
flowchart LR
    AD[Admin user] -- ask for role --> REQ[PIM request - role + window]
    REQ -- MFA required --> APP[Approver - MFA + reason]
    REQ -- approved --> GR[Time-boxed grant - 30 minutes]
    GR -- every action recorded --> AU[Audit log - activation id]
    GR -- expiry clock is enforced --> EX[Auto-expired]
```

```mermaid
flowchart LR
  U[Admin user] -->|request elevation to X role| A[Approver flow]
  A -->|approve + MFA + just reason| G[JIT grant - time-boxed 30 min]
  G -->|user performs task| L[Audit log + session record]
  L -->|expiry clock| E[Grant auto-expires]
  E --> R[Re-evaluate next time - per request]
```

## Elevation, step by step

```mermaid
sequenceDiagram
  participant A as Admin
  participant P as PIM system
  participant App as Target app / cloud
  participant Log as Audit store

  A->>P: request role "Global Admin" for 30 min
  Note over P: approved - MFA required, reason logged
  P->>App: activate role with activation notice
  App->>A: elevated access to scope
  A->>App: perform task
  App->>Log: every action attributed to A + activation ID
  Note over P: timer ends - role deactivated automatically
```

The properties that make PIM meaningful: **MFA on the request**, a **reason** that reviewers can challenge, a **scope** (which resource, not "everything"), an **expiry** that is enforced not remembered, and **audit logs** that tie each elevated action to its activation.

## Standing access vs just-in-time

| | Standing access | Just-in-time (PIM) |
| --- | --- | --- |
| State by default | Always elevated | User only (least privilege) |
| Window | Permanent | Minutes-hours, enforced |
| When attacks happen | Credential steal = instant admin | Steal still needs approval + MFA + reason |
| Review burden | "Why is everyone still admin?" | Per-activation, auditable |
| Risk profile | Fat target | Sparse, recorded |

PIM is **zero trust for humans**: just like short-lived workload credentials ([workload identity](../workload-identity-and-mtls)), the value is in the *living* time window.

## Break-glass access

PIM must never become a lockout. **Break-glass** is a separate, rarely-used, heavily-audited path (paper-sealed credentials, dormant emergency accounts, a runbook) for when normal processes are down. Govern it: credentials in a sealed vault, alerts on any use, quarterly verification that it still works — and that its use is treated as an incident until proven benign.

## Tester checklist

- Activate a role and confirm **auto-expiry** revokes access on schedule even if the user forgets to end it.
- Verify the approval gate cannot be bypassed: no MFA, no reason, no role — and no one can self-approve.
- Audit drill: pick a completed activation and trace every elevated action back to that activation ID and reason.
- Test break-glass end-to-end: sign in with the emergency creds, confirm the incident alert fired, and that creds still work after six months of no use.
